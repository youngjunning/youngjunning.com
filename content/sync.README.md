# 双站内容与模块协议

硅基紫升面向公司读者，硅基俊宁面向公开读者。两站使用相同的 schema 语义、蒸馏方案和功能模块，分别维护 UI、身份、部署与受众策略。同一事件或文章跨站保留稳定 ID；内容版本和数据数量可以不同。

## 受众边界

| 内容 | 公司站 | 公开站 |
| --- | --- | --- |
| 已确认可向双方披露的文章、经历和知识资料 | 公司读者适用版本 | 公开读者适用版本 |
| 公司项目、内部指标、业务资料和原始证据 | 仅限获准内部共享的版本 | 仅限脱敏后仍保真的版本 |
| 求职意向、面试安排、薪资谈判、私人联系方式、住址、证件、家庭及健康心理资料 | 未经针对公司读者的明确授权不接收；已公开也不等于允许向公司同步 | 逐项判断公开授权；私密原文留在明确配置的个人私有存储或本机 |
| 同时含公司秘密和个人敏感信息的材料 | 不接收整份原文 | 不接收整份原文 |

公司站不是个人私密存储。private、draft 和 UI 隐藏不保护源码、附件与 Git 历史；未经审查的内容不先写入目标仓库再删除。原始证据和跨目标映射只能留在有权接收它们的位置，个人私密资料的精确出处不能进入公司仓库。

审查覆盖正文、元数据、标签、来源、文件名、链接、封面、截图和附件，以及搜索、API、图谱和模型上下文。脱敏后仍暴露关键事实或无法保留原意时，跳过该方向。关键词检查只是辅助，不能证明完成受众审查。

## 共用模块范围

两站的目标能力包括个人资料与履历、个人记录、文章与阅读、收藏与概念笔记、Skills 清单与触发统计展示、关系图谱、来源检索与对话、工程资料与 Wiki、OKR。模块可在无获准内容时为空；模块可用和数据同步是两项验收。

记录与收藏共用字段、类型、日期精度、关系、去重和变化规则；目标对可接收内容施加额外检查。private 的展示过滤和公开仓库拒收属于目标策略，不能借此改变字段语义。文章共用稳定 ID、标题、摘要、真实日期、主题、标签、草稿与资源语义；HTML、历史迁移、ATA 出版信息和路径差异应通过兼容实现或目标适配处理，缺失支持必须报告。

修改 schema、蒸馏分支或模块时核对另一端实现。验收记录应区分已实现、待实现和受众策略差异；只创建文件、空数据或导航入口不算完成模块。数据中的密钥、原始仓库历史和业务材料不随能力迁移。

`scripts/compare-content-contract.mjs` 明确列出共用核心：记录与收藏模型、文章解析与资源处理、审核同步器、问答与推荐问题、工程证据、Wiki、OKR、Skills 统计的类型和校验，以及共用操作脚本和本文。执行 `npm run schema:compare -- <另一站仓库根目录>` 逐文件比较；差异或文件缺失时失败。UI、接收方校验、代码平台授权、模型服务和部署配置使用各自适配器，不把内部默认地址带入公开源码。

该命令只读显式指定的仓库，不在构建或线上请求中读取另一站。比较通过只证明清单中的实现相同，不证明文章内容相同、数据已获授权、功能已通过页面验收或站点已部署。

| 模块 | 共用能力 | 接收方差异 |
| --- | --- | --- |
| 记录、履历与收藏 | 独立稳定 ID、真实时间、出处、关系、发现与使用状态 | 只投影获准向该读者展示的内容 |
| 文章与阅读 | Markdown；HTML 与同名 meta.json；日期、主题、标签、草稿、出版信息；原文、引用与图谱 | 标题、来源、资源和正文可因脱敏不同；历史独立版本不强制合并 ID |
| 工程资料与 Code Brain | 固定 commit、文件摘要、源码片段、原生 AST、符号与静态关系检索 | 来源范围独立确认；公司工程数据不迁入公开站，公开范围允许为空 |
| Wiki、对话与推荐 | 原文引用校验、资料归属、模型综合与本人事实分离；Codex 维护时预先准备 Wiki 和推荐题，构建只校验并打包；指纹过期需重新整理 | 只检索本目标数据；在线问答的模型服务也是资料接收方，须有相应授权 |
| OKR 与 Skills 统计 | 同一校验、周期与进度语义、覆盖范围与可核验计数 | 不复制公司目标或未经授权的个人使用统计；空数据如实展示 |
| 写作管理 | 稳定 ID、真实日期、草稿和目标文章格式 | 公开界面提供稿件导出，源码写入沿用授权维护流程，不开放匿名写入 |

## 文章与其他内容的同步

文章是独立增量同步分支。每轮处理新写、实质修订、撤回的文章与已知未完成项；不因个人记录或收藏没有新增而跳过文章，也不默认批量同步历史文章。

先读取双方同 ID 的实际版本，针对接收方审查全文和资源，再通过补丁写入目标。同步保留作者立场、事实、真实日期与未知项；标题、文件名和来源表述可以因脱敏而不同。资源必须经过内容审查、具备使用权限并能在目标访问；公司内部 CDN 不能作为公开站资源入口。修订时重新审核，保留目标独立修订，核对引用与关联 ID；不凭相同 ID 或不同文件指纹直接认定同步完成或过期。

每个目标独立执行其约定的内容检查、测试、类型检查、构建及必要页面验收，再按授权提交和推送本任务改动。分别报告两个方向的已同步、无本轮待同步变更、跳过原因或未完成原因；提交、推送、部署、线上阅读与 ATA 同步分别验收。

此流程由维护会话执行，不代表部署了后台监听或定时同步服务。

## 可执行文章审核与同步

`article:sync` 是只读规划器。每个方向显式提供来源仓库、接收方和私有审核账本；账本必须位于两仓库之外，不能提交到任一仓库。它可能包含被拒收标题、个人敏感出处、源稿摘要与跨站对应关系，不能用公司仓库代替个人私有存储。

```sh
npm run article:sync -- --source <来源根目录> --ledger <本机私有审核账本.json> --audience public
npm run article:sync -- --source <来源根目录> --ledger <本机私有审核账本.json> --audience company
npm run article:sync -- --source <来源根目录> --ledger <本机私有审核账本.json> --audience public --patch
```

默认只输出各状态的数量。`--details` 额外输出源 ID、标题、指纹和审核原因，仅供本机私有审查；不放入公开报告、公司日志或接收方源码。`--patch` 仅输出获准接收版的补丁，由维护者按项目约定审核和应用，不直接写入文章或上传资源。

账本 version 为 1，reviews 为审核数组；历史批量任务另以 scopeIds 固定本次明确授权的源 ID，避免导入后的文章再次反向循环。每条审核包含 sourceId、audience、sourceSha256、reviewer、reviewedAt、decision 和具体 reason。源指纹覆盖正文、文件身份与元数据，HTML 还包括元数据文件的实际字节摘要。

| decision | 必要信息与行为 |
| --- | --- |
| approved / redacted | 完整接收版 targetText 与 targetSha256；原资源 resources 及接收方 targetResources 的相对文件、摘要和 URL 绑定。接收版保留源稳定 ID |
| skipped | 针对此文及此方向的拒收原因，不向接收方写入原文、附件或拒收清单 |
| equivalent | 显式确认既有独立版本的 targetId 与 targetSha256；只确认对应关系，保留各自 ID 和受众限定，不回灌被省略的信息 |

HTML 接收版声明 targetKind=html，另提供 targetMetadataText 与 targetMetadataSha256，正文和同名 meta.json 作为一对处理。更新已有目标时提供 previousTargetSha256；HTML 还提供 previousTargetMetadataSha256。既有 HTML 独立版本的对应审核同样绑定元数据摘要。

资源摘要必须对应本地实际文件；接收方封面、资源映射和嵌入资源均须绑定审阅过的字节与实际 URL。Markdown 资源按阅读器使用的解析链识别，代码示例中的图片和 CSS 字面量不当作实际配图。HTML 的图片、脚本、样式、媒体等资源同样检查，内嵌 data 内容随整份审核文本固定。资源内容还须经过视觉、隐私与使用权限审查；摘要或关键词匹配不能替代这项判断。只搬运接收版实际使用的合格资源，上传按目标既有流程完成并回读校验。

源正文、元数据或原资源变化产生 review-stale / resource-review-stale；接收方资源变化产生 target-resource-review-stale。已有接收版完整命中审核版本才返回 synced。目标独立修改、文件名冲突和独立对应版变化分别报告冲突或过期，不能强行覆盖。源稿撤回只报告 source-withdrawn，先核对接收方是否独立维护，再决定是否撤回。改名保留 ID，并成对处理 HTML 元数据；源草稿不自动发布。

历史文章的批量授权和精确范围记录在个人接入配置与私有账本，不固化进通用 Skill。日常收尾按本轮新写、实质修订、撤回及已知待处理项执行；普通进度、迁移操作和资料中的第一人称不因此成为本人记忆。

模型传输适配与检索引擎按站点分别维护。公开站使用 DeepSeek 与本地检索；内部站点可使用不同模型与检索引擎。引擎适配、原生解析及其构建脚本不属于必须同步的核心，不因协议一致而复制运行依赖或凭证。
